# データエンジニアリング基礎ノート

## 1. 定義と背景
- **データ集約型 (Data-Intensive)**: CPUパワーよりもデータの量・複雑さがボトルネックとなるアプリケーションの性質。
- **データエンジニアリングの役割**: 生データを取り込み、分析や機械学習（ダウンストリーム）をサポートする、高品質で一貫性のある情報を生成するシステムを構築・保守すること。

## 2. データエンジニアリング・ライフサイクル
1. **生成 (Generation)**: ソースシステムでのデータ作成。
2. **取り込み (Ingestion)**: バッチ・ストリーミングによる収集。
3. **保存 (Storage)**: データを保持する基盤。
4. **変換 (Transformation)**: クレンジング、モデル化による価値創造。
5. **提供 (Serving)**: 利用者（分析、ML）への配信。

### 底流 (Undercurrents)
- セキュリティ、データマネジメント、DataOps、オーケストレーション。

## 3. ストレージ技術

| 特徴 | Bツリー | LSMツリー |
| :--- | :--- | :--- |
| **主な用途** | RDB (MySQL, PostgreSQL) | NoSQL (Cassandra, RocksDB) |
| **得意な処理** | 読み取り (Read) | 書き込み (Write) |
| **更新方式** | ページの上書き | ログへの追記 |
| **内部構造** | 固定サイズページ分割 | メンテーブル + SSTable |

## 4. 分散システムの設計
- **レプリケーション**: データのコピーを複数ノードに保持。高可用性と低遅延を実現。
- **パーティショニング (Sharding)**: データを分割してスケーラビリティを確保。負荷の偏り（ホットスポット）に注意が必要。

## 5. 分析と運用
- **OLTP vs OLAP**: 行指向（取引）か列指向（分析）かの使い分け。
- **フィーチャーストア**: MLOpsにおける特徴量の一元管理。
- **リバースETL**: DWHの洞察を業務システムに書き戻し、アクションに繋げる。
